# 三库结构拦截及达梦查询元数据修复报告

日期：2026-10-28。

## 结论与原因

本轮按 MySQL、Oracle、达梦重新检查迁移和归档的字段结构阻断分支：有确定源定义的真实差异必须生成对应目标方言 DDL；不因历史数据、非空约束放宽或容量收窄省略。派生查询元数据的误报应消除，不能靠生成无效 ALTER 掩盖。

用户确认截图来自达梦，且是更新 Jar、重启后新建的任务。日志“归档查询字段类型与源表不同”比较的是范围查询结果与源物理表；并非源表与归档表。前次修复仅兼容 `ORACLE` 的 `NUMBER(0,-127)`，遗漏达梦数据库分支，因此新任务仍会误拦截，且该查询问题分支没有目标表 ALTER。

真实达梦验证复现了 `(0,-127)`，同时发现迁移零行派生查询还会丢失字段物理来源。真实 MySQL 验证也发现派生查询将 ENUM/SET 投影为 CHAR，导致生成器无法恢复成员。两者都需要修复元数据取得方式。

## 最终行为

| 检查项 | MySQL | Oracle | 达梦 |
|---|---|---|---|
| 任务所有表/步骤一次性收集 | 保持 | 保持 | 保持 |
| 目标缺字段/多字段 | ADD / DROP COLUMN | ADD / DROP COLUMN | ADD / DROP COLUMN |
| 类型、长度、精度、小数位差异 | MODIFY COLUMN | MODIFY | MODIFY |
| NULL 与 NOT NULL 双向差异 | 按源定义 MODIFY | 按源定义 MODIFY | 按源定义 MODIFY |
| 字段容量缩小、有历史数据 | 仍生成 DDL，交人工确认 | 同左 | 同左 |
| 查询未知精度 `(0,-127)` | 不套用 Oracle/DM 规则 | 限定 NUMBER 族兼容 | 限定精确数值同义族兼容 |
| 原生字段补读 | 完整 COLUMN_TYPE | 精确单表 JDBC 字段目录 | 精确单表 JDBC 字段目录 |
| 完全相同的重复建议 | 按字段语义合并 | 同左 | 同左 |
| 执行边界 | 二次确认、核对摘要及目标、遇错停止、不自动启动数据任务 | 同左 | 同左 |

迁移按源查询结果映射到目标方言；归档按源物理表定义。当前比对范围仍为字段集合、类型、长度/精度、小数位和可空性，不扩展为主键、索引、默认值、注释或字符集全量同步。

## 实现要点

- `ArchiveQueryMetadataSupport` 供归档汇总预检和最终准备流程共同使用：达梦只对 NUMBER/DECIMAL/NUMERIC/DEC 与 JDBC NUMERIC/DECIMAL 同义族、查询精度 0 且小数位 -127 进行兼容。Oracle 保持原限定；已知精度及非同义类型差异仍拒绝。每节点只记录一次兼容字段数。
- 迁移先调用原始 SQL 的 `PreparedStatement.getMetaData()`，不执行原始查询的数据行。驱动不支持时回退零行派生查询；明确来源字段可补读物理定义。
- 新增 `PhysicalColumnMetadataSupport`：MySQL 用绑定的库名、表名读取字段目录，保留 ENUM/SET 完整成员、大小写和转义；Oracle/DM 转义精确表名模式，并过滤实际模式/表名。没有扩大为全库扫描，缺失属性不伪造。
- 归档的汇总预检和后续准备使用一致的完整物理定义；缓存只在当前准备过程内有效，重新校验重新读取，避免执行 DDL 后看到旧定义。
- 补齐 MySQL ENUM/SET、浮点声明参数及合法数值修饰的 DDL；同样覆盖建表、增列和改列。原生属性不能因为 JDBC 投影丢失而静默退化为注释。
- MySQL 两侧完整 TEXT/BLOB 系列声明一致时，驱动因字符集换算产生的容量差异不再误拦截；不修改字符集，也不会产生执行后仍重复报错的同类型 ALTER。可空性及其他真实定义差异保持检查。
- 补齐可推导的跨库数值映射：`NUMBER(10,-2)` 到 MySQL 为 `DECIMAL(12,0)`，`NUMBER(4,5)` 为 `DECIMAL(5,5)`；`BIT(64)` 到 Oracle/DM 使用可容纳其无符号范围的 `NUMBER/DECIMAL(20,0)`。超出目标数据库精度能力仍明确说明。
- Oracle 驱动内部类型名 `INTERVALYM/INTERVALDS` 不能直接作为 SQL 类型。遇到这类物理字段时，单表绑定查询 `ALL_TAB_COLUMNS` 取得完整 `INTERVAL YEAR(p) TO MONTH` / `INTERVAL DAY(p) TO SECOND(s)` 声明，用于比较和 DDL；不把驱动返回的存储长度猜成声明精度，无法取得完整声明时明确报告缺失原因。
- 建表建议按排序后的字段签名、增改列按规范化定义判断是否相同；表名前缀、字段大小写或建表列顺序不同不再制造冲突。真实的类型、字段集合以及保留/删除矛盾仍列出候选。

Oracle 间隔类型的内部名称通过项目自带 `ojdbc8-19.22` 的 `OracleResultSetMetaData` 字节码核实；合法 SQL 语法和参数范围参照 [Oracle 官方数据类型说明](https://docs.oracle.com/en/database/oracle/oracle-database/18/sqlqr/Data-Types.html)。这是本地方言回归依据，不能替代真实 Oracle 执行验证。

源 SQL 无效、不可读取的字段目录、重复查询别名、游标/关联配置错误以及互相矛盾的源定义不是可单靠调整目标字段消除的结构差异。这些问题仍写明原因和修正方向；任意表达式没有确定精度时须显式 CAST，超出目标数据库类型能力时不能虚构可执行定义。

## 验证方式

Java 改动逐文件使用 JDK 8 `javac -encoding UTF-8 -source 8 -target 8 -implicit:none` 检查，依赖从既有 Jar 提取，输出位于忽略目录 `target/dm-query-metadata-check`。未运行 Maven、未重新打包 Jar/ZIP。

离线回归覆盖三方言字段增改删、NULL 双向、真实精度错误拒绝、跨表汇总、父表失败后子表继续、源定义冲突、完整原生类型、同步后两阶段回检和失败前零写入/删除。达梦同义类型及 JDBC 表示共 32 组，包含截图中的 `(20,0)/(14,0)/(8,0)/(12,4)`。

八项回归通过：`PhysicalColumnMetadataSupportCheck`、`ArchiveStructureValidationCheck`、`DamengSqlCompatibilityCheck`、`StructureValidationAggregationCheck`、`StructureSyncExecutionCheck`、`NumericCompatibilityCheck`、`ArchiveGraphValidationCheck`、`ColumnMappingCheck`。
