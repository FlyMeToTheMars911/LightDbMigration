# 源默认值同步修复报告

日期：2026-10-30。

## 问题与根因

现场截图中，源字段 `CCB_PART_MEMBER.VIP_LEVEL` 为 `VARCHAR2(3) DEFAULT ' ' NOT NULL`，生成的归档表建议却只有 `ADD ... VARCHAR(3) NOT NULL`。截图还记录另一字段新增失败：`-6609：违反列[MANUAL_FLAG]非空约束`。截图未提供该字段的完整源定义；不能据此推断它应使用什么默认值。

本地源码确认默认值在三处缺失：

1. `PhysicalColumnMetadataSupport` 未查询 MySQL `COLUMN_DEFAULT/EXTRA`，Oracle/达梦未读取 JDBC `COLUMN_DEF`，物理定义对象也不保存默认值。
2. 原归档代码只在类型、精度或可空性不足时补读 Oracle/达梦目录，普通字段不会读取默认值。迁移也只有类似的按需补读。
3. `ArchiveStructureValidator`、`MigrationEngine` 的 `CREATE/ADD/MODIFY` 只生成类型和可空性。Oracle/达梦修改字段且可空性相同时会省略重复约束，这个分支也没有默认值。

因此属于共用实现缺口，MySQL、Oracle、达梦都受影响。MySQL `MODIFY COLUMN` 还可能清除被省略的既有默认值。项目原本未做完整默认值一致性比较；本次按用户问题扩展“已有结构差异生成 DDL 时继承源默认值”的能力。

Oracle 另有驱动限制：项目自带 `ojdbc8 19.22.0.0` 的 `oracle.jdbc.driver.OracleResultSetMetaData` 中，`getTableName/getSchemaName/getCatalogName` 返回空串，不能据此判定字段是计算表达式。先通过本机 `javap -c` 检查驱动字节码确认，再在真实 Oracle 19c 验证普通单表来源回退及默认值继承。

## 修复行为

- 物理字段保存“无默认值”“未知”“已取得的默认值”，未知不伪装成无默认值。
- MySQL 精确单表查询读取 `COLUMN_DEFAULT/EXTRA`，区分字符串与表达式，保留空串、空格、单引号和数字零；`DEFAULT_GENERATED` 即使是常量也保留表达式括号，避免 TEXT/JSON 等类型生成非法默认值。兼容 MariaDB 10.2.7+ 的已引用目录格式，按服务端版本识别，不能通过值是否带引号猜测；MariaDB TEXT/JSON 常量也保留括号。10.2.1～10.2.6 已支持默认表达式但目录无法可靠区分，保守转人工处理。Oracle/达梦通过精确表名及转义模式读取 `COLUMN_DEF`，保留引号内空格。
- 同库归档全部源物理表补读默认值并按表缓存。迁移优先用 JDBC 物理来源；驱动无来源时，严格识别普通单表查询的星号、直列和别名，按真实源列补读。明确计算表达式不继承物理默认值，复杂且无法确认来源的列保持未知。
- `CREATE/ADD/MODIFY` 均携带可确认的源默认值。Oracle/达梦省略重复 `NULL/NOT NULL` 时继续保留 `DEFAULT`。默认值参与同一物理目标建议的去重与冲突判断。
- 跨库只自动保留明确字面量及公共 `CURRENT_TIMESTAMP`；其他函数、序列、国家字符集字面量跨库、空串跨库和含反斜杠的值给出人工处理方向。MySQL 非表达式二进制默认值的目录文本也不当成普通字符串，需用 `SHOW CREATE TABLE` 人工核对原始字节。未确认的列不输出缺少默认值的可执行 DDL，其他可检查表和字段继续汇总。

截图对应建议会保留源空格默认值，例如：

```sql
ALTER TABLE "CCB_FIL_PART_MEMBER" ADD ("VIP_LEVEL" VARCHAR(3) DEFAULT ' ' NOT NULL);
```

本次没有对现场截图中的业务表执行任何语句。源没有默认值时不补造空格或零；历史 NULL、类型收窄、主外键等问题仍须在执行前审核。仅默认值不同不单独触发结构预检失败，也不额外删除 Oracle/达梦目标现有默认值。主键、索引、注释等完整 DDL 属性不在本次扩展范围。

## 真实达梦验证

使用用户截图授权的测试库，单次物理登录，不自动重试；只操作本轮前缀 `LDM_DEF_4C88356102` 的六张精确隔离表。源字段包含空格默认值、字符零、数字零及 `O'Brien` 引号字符串；目标表预置一条历史数据并缺少三个非空字段。

迁移与归档各验证一组：生产 `prepare` 失败后生成三条 `ADD` 和一条 `MODIFY`；执行建议后，历史行新增字段使用源默认值，既有字段历史值保持，后续仅插入 ID 的新行取到源默认值；物理 `DATA_DEFAULT` 与源一致，重新执行完整预检通过。另以缺表场景验证 `CREATE` 携带默认值，建表后省略字段插入及重新预检通过。

结果为 `COLUMN_DEFAULT_DM_INTEGRATION_CHECK_PASSED`，两种模式均通过，清理残留为 0。失败预检及重新预检期间均没有业务数据写入或删除，未启动数据迁移/归档任务。SQL、绑定参数、真实默认值目录、查询列来源、执行结果及清理语句全部见[达梦实测 SQL 记录](源默认值同步达梦实测SQL记录.md)。驱动内部登录初始化和元数据内部 SQL 无法取得原文，记录中已说明。
