# 结构脚本确认执行验证报告

日期：2026-10-26。

本报告记录确认执行功能首次交付时的范围。2026-10-28 起字段同步扩展为源定义全量对齐，包含可空性双向修改和 `DROP COLUMN`；当前规则及实测见[全字段结构同步验证报告](全字段结构同步验证报告.md)。以下记录保留原版本验证边界。

## 功能与操作

任务日志的“表结构同步建议脚本”区域新增“执行脚本”按钮。点击后弹出二次确认，展示任务名称、原目标数据库和可执行条数；确认后执行，取消不发请求。脚本保持只读，复制和下载功能保留。

归档读取页面源库连接，迁移读取目标库连接。后端在登录前核对明确确认、服务端脚本摘要、原任务目标连接和脚本目标表；客户端不提交 SQL。原任务必须处于失败状态，脚本必须包含可执行的建表、增列或改列建议。只有说明、被注释的危险操作和冲突候选不会执行。

执行使用独立状态，显示总条数、成功条数和结果；同一份脚本只允许一次执行，执行中不能清除任务。连接失败或某条 SQL 失败立即停止，不自动重试，已经成功的 DDL 可能已生效。执行结束不自动启动数据迁移/归档，原任务仍保持失败状态；处理剩余人工项目后应重新创建任务预检。

## 接口变化

```text
POST /api/tasks/{id}/structure-sync/execute
{ confirmed: true, scriptDigest: "当前任务摘要", database: { ...数据库连接字段... } }
```

`database` 复用既有 `DatabaseConfig` 对象。返回仍采用既有 `{success, data}` 包装，`data` 为任务详情。任务详情新增 `structureSyncDigest` 和 `structureSyncExecution`：

| 字段 | 含义 |
|---|---|
| `status` | `READY`、`RUNNING`、`SUCCEEDED`、`FAILED` |
| `totalStatements` | 可执行语句总数 |
| `executedStatements` | 已返回成功的语句数 |
| `message` | 当前进度或结果说明 |

前置校验失败返回 HTTP 400，不登录数据库，也不占用执行机会。进入执行后发生数据库错误，返回包含独立 `FAILED` 状态的任务详情，保留成功条数。每条 DDL 超时 300 秒；连接沿用既有超时策略。

任务结束后原密码会被清除，所以执行时从当前表单临时提交连接。执行请求所有返回路径清除请求中的密码，不写入任务详情、状态、文档或日志。具体 SQL 写后台 SQL 日志，页面任务日志显示序号和结果。网络中断不自动重复提交，页面通过任务详情轮询核实状态。

## 真实 MySQL 验证

使用用户此前提供的测试数据库，每轮只登录一次，关闭自动重连；连接信息经环境变量和标准输入传入，没有保存至测试源码或文档。隔离前缀为 `LDM_SE_<时间戳>`，先检查对象不存在，再创建 6 张本轮测试表。测试使用真实生产预检生成建议，通过注入连接开器的记录代理调用公开 `StructureSyncService.execute`，校验、摘要、占用和执行路径均为生产实现；仅复用管理连接以记录完整 SQL，没有替换执行逻辑。

实测通过：

1. 迁移任务：未确认时零连接；确认执行扩容和增列两条建议，真实结构正确并保留 `NOT NULL`；重复提交不再请求连接或执行 SQL。
2. 归档任务：同样完成两条结构建议；源记录保留、归档表仍为空，证明没有自动开始归档删除或数据写入。
3. 部分失败：预检生成两条增列建议后，测试先手工补入第二个字段。确认执行时第一条成功，第二条因字段已存在而失败；记录成功 1/2，第一条真实生效，之后重复提交被拒绝。
4. 原失败任务状态不变，全部临时请求密码被清除；6 张本轮隔离表已全部清理，残留 0。

全部实际执行的应用侧 SQL、元数据 API、逻辑连接关闭和清理顺序见[实测 SQL 记录](结构脚本执行实测SQL记录.md)。本轮预检和 DDL 没有绑定参数。JDBC 驱动登录初始化及元数据 API 内部 SQL 不由应用显式执行，无法从记录代理取得原文，已在记录中说明。

## 验证边界

真实执行验证为 MySQL；Oracle 和达梦未连接真实数据库。HTTP 检查验证了页面资源和接口注册/拒绝路径，真实 DDL 在公开执行服务中验证；没有把二者表述为浏览器到数据库的完整端到端实测。前端确认交互使用 jsdom，未做真实浏览器实点测试。
