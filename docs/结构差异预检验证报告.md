# 结构差异预检验证报告

日期：2026-10-26。

## 修复后的行为

迁移和归档在数据变更前检查本任务所有配置表/SQL 步骤，一次性汇总可识别的问题，并同步返回 `structureSyncScript`。归档使用独立的字段结构预检，主表失败不影响其他主表和子表的结构检查；字段数量不同仍继续比较缺失、多余和同名字段定义。存在任意结构问题时，任务失败，不执行数据写入或源记录删除。

建议脚本包括完整问题清单和可推导的 DDL。未知类型、额外字段、直接放宽非空约束和目标配置冲突只给人工处理说明。迁移同一目标字段出现不同建议时撤销该字段可执行 DDL；MySQL 扩容建议保留目标原有 `NOT NULL`。建议脚本由人工审核执行，工具不会自动执行。

Oracle 修改列时只在确需收紧约束时追加 `NOT NULL`，字段可空性不变时仅修改类型，避免重复声明已有规则引发 [ORA-01451](https://docs.oracle.com/en/error-help/db/ora-01451/) 或 [ORA-01442](https://docs.oracle.com/en/error-help/db/ora-01442/)。该方言行为通过离线回归检查，尚未在真实 Oracle 执行。

此要求同时写入根目录 [AGENTS.md](../AGENTS.md)、[README](../README.md)、开发设计及操作手册，作为后续改动必须保持的约束。

## 本地检查

Java 改动使用 JDK 8 单文件 `javac -encoding UTF-8 -source 8 -target 8 -implicit:none`，按辅助类、调用方、测试文件的依赖顺序逐个检查，输出到忽略目录 `target/structure-validation-check`，不覆盖既有交付 Jar。未使用 Maven 编译或打包。

定向检查入口：

| 检查类 | 覆盖内容 |
|---|---|
| `ArchiveStructureValidationCheck` | 同表多个差异、多主表和子表汇总、父失败子继续、缺表、多余列、未知类型、零写入/删除、非空约束放宽只给说明、目标物理别名冲突，以及 MySQL/Oracle/DM 方言 |
| `StructureValidationAggregationCheck` | 迁移跨步骤汇总、源元数据普通失败后继续、数值字段读取失败后检查下一字段、脚本去重和冲突说明、控制字符处理、保留目标非空约束 |
| `NumericCompatibilityCheck` | 既有数字范围及精度兼容性规则 |
| `ArchiveGraphValidationCheck` | 既有多主表及父子关系校验 |
| `DamengSqlCompatibilityCheck` | 既有达梦 SQL 方言和类型兼容行为 |

运行方式：将本轮 `test-classes`、`classes` 放在 classpath 前面，随后加入既有 `target/classes`、定向编译的测试和本地依赖。实际执行的命令形态：

```powershell
javac -encoding UTF-8 -source 8 -target 8 -implicit:none -sourcepath '' -cp $checkCp -d $checkClasses <单个Java文件>
java '-Dfile.encoding=UTF-8' -cp $runtimeCp com.hundsun.lightdbmigration.service.ArchiveStructureValidationCheck
java '-Dfile.encoding=UTF-8' -cp $runtimeCp com.hundsun.lightdbmigration.service.StructureValidationAggregationCheck
java '-Dfile.encoding=UTF-8' -cp $runtimeCp com.hundsun.lightdbmigration.service.NumericCompatibilityCheck
java '-Dfile.encoding=UTF-8' -cp $runtimeCp com.hundsun.lightdbmigration.service.ArchiveGraphValidationCheck
java '-Dfile.encoding=UTF-8' -cp $runtimeCp com.hundsun.lightdbmigration.service.DamengSqlCompatibilityCheck
```

## 真实 MySQL 验证

使用用户指定的 `10.20.36.154:3306/hs_aio_blank`，每轮只进行一次物理登录，关闭自动重连。凭据仅经进程输入传入，不保存至源码、文件或日志。测试入口为 `StructureValidationMysqlIntegrationCheck`，通过反射调用生产 `ArchiveEngine.prepare` 与 `MigrationEngine.prepareAllSteps`；成功后继续调用生产批次归档/迁移方法，不使用测试替代实现。

每轮采用随机前缀 `LDM_SV_<时间戳>`，先确认对象不存在，再创建 10 张本轮隔离表。脚本应用前严格解析 `ALTER/CREATE TABLE` 的目标，只允许本轮目标表白名单。测试过程不读写现存业务表。结束时按登记的对象逐表清理，任一对象清理失败仍继续其余对象；SQL 记录失败也会关闭连接。

验证步骤及结果：

1. 两张归档主表、两级子表分别构造长度不足、缺字段、多余字段、类型不一致和归档表不存在等问题；一次预检同时给出全部表的问题及建议。
2. 通过连接代理统计数据变更语句，结构失败期间 `INSERT/UPDATE/DELETE/MERGE` 次数保持不变，源记录仍保留。
3. 人工审核并执行本轮隔离对象的建议 DDL；多余字段按测试预期手工处理。重新预检通过后执行实际归档，4 张源表各 1 行全部归档，4 张归档表各有 1 行。
4. 两步迁移同时构造缺字段及长度不足；一次性输出两步问题与脚本，预检失败零写入。
5. 验证未限定表名与显式默认库名指向同一物理目标：相同建议去重，不同建议只给注释；执行普通差异建议后确认原 `NOT NULL` 保留，重新预检通过，两张迁移目标表各写入 1 行。
6. 清理全部本轮测试表，残留数量为 0。

真实库入口命令为：

```powershell
java '-Dfile.encoding=UTF-8' -cp $runtimeCp com.hundsun.lightdbmigration.service.StructureValidationMysqlIntegrationCheck
```

连接地址、端口、库名、用户和 SQL 记录路径通过 `LDM_TEST_MYSQL_*`、`LDM_TEST_SQL_RECORD` 环境变量指定；密码只读取一次标准输入。实际执行的全部应用侧 SQL、绑定/批次参数、JDBC 元数据 API、提交/回滚及清理顺序列于 [实测 SQL 记录](结构差异预检实测SQL记录.md)。记录保留每一轮，不以新轮次覆盖旧轮次。JDBC 驱动内部初始化及元数据 API 的内部 SQL 无法从应用代理获取原文，记录中明确区分。

## 验证范围

真实数据库验证为 MySQL 同库场景；Oracle 和达梦建议方言通过离线 JDBC 代理验证，未连接真实 Oracle/达梦数据库。前端沿用已有任务详情脚本展示、复制和下载能力，本次未修改前端，未做浏览器实点验证。

检查范围仍是迁移写入兼容性与归档字段定义，不包括全库主键、索引、默认值、字符集或注释的完整同步。结构元数据无法读取时会报告原因并继续检查其他表，不宣称已获得该表所有字段差异。连接故障、终止、中断立即退出。预检成功后不提供数据库 DDL/数据并发快照，执行阶段仍依赖原有事务、安全校验和维护窗口。

本次没有更新 `target` 下的交付 Jar/ZIP；发布时需使用更新后的源码按既有交付流程重新打包。
