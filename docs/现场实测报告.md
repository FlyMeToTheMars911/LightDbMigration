## 4. 第二轮回归与后续修复

在仅调整“终止时 JDBC 驱动取消失败的日志降噪”后执行第二轮回归。专用表事前检查、建表和测试数据准备均成功，但两个迁移任务的新数据库连接持续无响应并超过 120 秒；没有进入结构校验或迁移 SQL 阶段。测试程序没有重新创建任务或重试登录，向两个任务发出终止请求后未能在 10 秒内确认终态，但仍完成全部专用表清理及不存在复查。随后通过进程 ID 和完整命令行确认并停止本项目测试服务进程，避免继续占用连接。

该现象暴露出仅依赖 JDBC 驱动登录超时不够可靠。最终代码新增 15 秒应用级连接看门狗：即使驱动不响应线程中断，任务线程也能在 15 秒后明确失败或按终止标记退出，迟到连接会被关闭，连接线程设为守护线程，不再阻止服务退出。

为避免继续触发现场连接限制，该修复没有再次访问现场库；改用不响应中断的模拟 JDBC 驱动验证，结果为：

```text
[PASS] application connection watchdog costMs=15007
```

因此验证边界如下：

- 迁移主流程：已由第一轮真实 MySQL/Oracle 完整验证。
- 连接看门狗：已由本地模拟不响应驱动验证，未再次连接现场库。

### 6.5 第一轮迁移服务生成的 SQL

以下列出应用直接创建的 SQL 模板。`?` 为 JDBC 参数；同一模板按实际批次数批量执行。JDBC 驱动在 `DatabaseMetaData.getColumns/getPrimaryKeys/getIndexInfo` 内部使用的系统目录 SQL 由驱动生成，应用无法取得其具体文本，调用类型已在此明确记录。

```sql
-- MySQL -> Oracle，第 1 步源查询
SELECT ID, CODE, AMOUNT, CREATED_AT, NOTE FROM LDM_IT_MY_SRC_829;

SELECT * FROM (
    SELECT ID, CODE, AMOUNT, CREATED_AT, NOTE FROM LDM_IT_MY_SRC_829
) LM_SOURCE WHERE 1 = 0;

SELECT * FROM <ORACLE_TEST_SCHEMA>.LDM_IT_ORA_D1_829 WHERE 1 = 0;

SELECT COUNT(*) FROM (
    SELECT ID, CODE, AMOUNT, CREATED_AT, NOTE FROM LDM_IT_MY_SRC_829
) LM_COUNT;

SELECT MAX(LM_SOURCE.`ID`) FROM (
    SELECT ID, CODE, AMOUNT, CREATED_AT, NOTE FROM LDM_IT_MY_SRC_829
) LM_SOURCE;

-- 首批一次
SELECT LM_SOURCE.* FROM (
    SELECT ID, CODE, AMOUNT, CREATED_AT, NOTE FROM LDM_IT_MY_SRC_829
) LM_SOURCE
WHERE LM_SOURCE.`ID` <= ?
ORDER BY LM_SOURCE.`ID` ASC
LIMIT 37;

-- 后续 6 批
SELECT LM_SOURCE.* FROM (
    SELECT ID, CODE, AMOUNT, CREATED_AT, NOTE FROM LDM_IT_MY_SRC_829
) LM_SOURCE
WHERE LM_SOURCE.`ID` > ? AND LM_SOURCE.`ID` <= ?
ORDER BY LM_SOURCE.`ID` ASC
LIMIT 37;

-- Oracle MERGE，同一模板批量绑定 250 行，共 7 批
MERGE INTO <ORACLE_TEST_SCHEMA>.LDM_IT_ORA_D1_829 LM_T
USING (SELECT ? "ID", ? "CODE", ? "AMOUNT", ? "CREATED_AT", ? "NOTE" FROM DUAL) LM_S
ON (LM_T."ID" = LM_S."ID")
WHEN NOT MATCHED THEN
INSERT ("ID", "CODE", "AMOUNT", "CREATED_AT", "NOTE")
VALUES (LM_S."ID", LM_S."CODE", LM_S."AMOUNT", LM_S."CREATED_AT", LM_S."NOTE");

-- MySQL -> Oracle，第 2 步；结构、总数、最大值和分页包装方式同上，源查询如下
SELECT ID, CODE, AMOUNT, CREATED_AT, NOTE
FROM LDM_IT_MY_SRC_829
WHERE ID <= 13;

-- 目标结构检查
SELECT * FROM <ORACLE_TEST_SCHEMA>.LDM_IT_ORA_D2_829 WHERE 1 = 0;

-- Oracle MERGE 模板同上，目标表为 LDM_IT_ORA_D2_829，批量绑定 13 行，共 1 批

-- Oracle -> MySQL 源查询及包装
SELECT ID, CODE, AMOUNT, CREATED_AT, NOTE
FROM <ORACLE_TEST_SCHEMA>.LDM_IT_ORA_SRC_829
ORDER BY ID;

SELECT * FROM (
    SELECT ID, CODE, AMOUNT, CREATED_AT, NOTE
    FROM <ORACLE_TEST_SCHEMA>.LDM_IT_ORA_SRC_829
    ORDER BY ID
) LM_SOURCE WHERE 1 = 0;

SELECT * FROM <MYSQL_TEST_DATABASE>.LDM_IT_MY_DST_829 WHERE 1 = 0;

SELECT COUNT(*) FROM (
    SELECT ID, CODE, AMOUNT, CREATED_AT, NOTE
    FROM <ORACLE_TEST_SCHEMA>.LDM_IT_ORA_SRC_829
    ORDER BY ID
) LM_COUNT;

-- 单次流式执行上面的原始源查询，目标分 5 批绑定 120 行
INSERT IGNORE INTO <MYSQL_TEST_DATABASE>.LDM_IT_MY_DST_829
(`ID`, `CODE`, `AMOUNT`, `CREATED_AT`, `NOTE`)
VALUES (?, ?, ?, ?, ?);

-- 暂停/继续/终止任务的源查询
SELECT ID, CODE, AMOUNT, CREATED_AT, NOTE FROM LDM_IT_MY_SRC_829;

SELECT * FROM <ORACLE_TEST_SCHEMA>.LDM_IT_ORA_CTL_829 WHERE 1 = 0;

-- 使用与第 1 步相同的结构、总数、最大值和 Keyset 包装，LIMIT 为 1
-- Oracle MERGE 绑定并提交 2 行后终止
```
