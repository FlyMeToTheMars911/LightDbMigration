# Light DB Migration

面向现场实施人员的轻量级 MySQL/Oracle/达梦数据迁移与同库归档工具。服务启动后，数据库配置、迁移/归档规则、批次大小、任务控制、进度和日志全部在浏览器页面中操作。最近一次数据库配置（含密码）使用 AES-GCM 加密保存在服务本机，重启后自动回填，且不会进入日志。

## 主要能力

- JDK 8 单 Jar 服务，现场交付包自带 Java 运行环境，无需安装 JDK 或前端运行环境。
- 支持 MySQL、Oracle、达梦（DM）作为迁移源库或目标库，不使用存储过程。
- 支持同库数据归档：一个任务可配置多张主业务表，将各自主表选定数据写入同结构归档表，并在批次成功后删除对应源记录。
- 支持多级关联从表；每张从表可选择任一主表或另一张从表作为上级，并配置“本表字段=上级表字段”，形成多根、单上级、可分支的有向无环关系。
- 归档每批严格按“父节点到子节点写归档表 → 子节点到父节点清理源表 → 提交”递归执行，任一节点失败都会回滚当前主表批次。
- 归档 SLF4J 后台日志记录实际执行的结构校验、统计、分页、写入、残留校验和删除 SQL；参数化查询记录绑定参数，批量写入记录 SQL 模板和批量行数，具体 SQL 不返回前端任务日志。
- 一个任务支持多条查询 SQL，先整体校验结构，再按顺序逐条迁移。
- 结构预检一次性汇总全部步骤的问题；失败后可在页面复制或下载目标表结构同步建议脚本。
- 普通查询采用流式读取；页面可指定任意类型的递增唯一字段启用带上界的游标分页，不依赖数据库自增标记。
- 默认跳过重复数据；MySQL 使用 `INSERT IGNORE`，Oracle 优先使用主键/唯一键 `MERGE`，达梦在批量插入遇唯一键冲突时回滚当前批次，再逐行跳过重复。
- 达梦目标或归档表的 `IDENTITY` 自增列支持保留源 ID，支持 CLOB/BLOB 及空值迁移。
- 支持多个任务、批次级进度和耗时、网页日志，以及暂停、继续、终止。
- 每个任务使用独立数据库配置；任务状态在服务重启后清空，最近一次数据库配置可自动恢复或在页面主动清除。
- 支持迁移/归档规则导出为 JSON，由现场人员导入回填；数据库连接配置不导出，导入也不覆盖现场连接。

## 开发打包

项目使用 Maven 管理依赖，打包环境要求 JDK 8 和 Maven 3.6.3 及以上版本。开发人员执行一次命令即可同时生成可执行 Jar 和现场交付 ZIP：

```text
mvn clean package -DskipTests
```

生成文件：

- `target/light-db-migration.jar`：可执行服务。
- `target/light-db-migration-<项目版本>.zip`：完整现场交付包，包含 Jar、`runtime/` Java 运行环境、README、Windows/Linux 启动脚本及完整 `docs` 文档目录。

默认将构建所用 Java 的安装目录打入 `runtime/`；JDK 8 自动使用其 JDK 根目录，保留运行库及原有许可证文件。不需要再手工复制文件或二次压缩。也可指定待交付的 64 位 JDK/JRE 8 目录：

```text
mvn clean package -DskipTests "-Dbundled.java.home=D:\delivery\jdk8"
```

运行环境必须与现场操作系统、CPU 架构匹配：默认包与构建所用 Java 平台一致，Windows 和 Linux 应分别打包；跨平台打包时用 `bundled.java.home` 指向目标平台已解压的 Java 目录。装配前会检查该目录是否包含 `bin/java.exe` 或 `bin/java`。

现场解压匹配平台的完整 ZIP 后直接运行启动脚本，不需要安装 Java、Maven、Node.js 或数据库客户端，也不需要配置 `JAVA_HOME`、`PATH`，启动时不会联网下载依赖。业务操作仍须具备数据库网络连通、账号权限及手册要求的备份等条件。完整说明见 [现场实施操作手册](docs/现场实施操作手册.md)，真实数据库验证见 [现场实测报告](docs/现场实测报告.md)，架构和核心实现见 [开发人员设计说明](docs/开发人员设计说明.md)。

达梦选择数据库类型 `DM`，默认端口 `5236`；Schema 可选，留空使用登录用户默认模式，填写时按普通标识符转为大写。高级连接可填写 `jdbc:dm://主机:端口?schema=模式名`，账号密码使用独立字段。驱动 `DmJdbcDriver18 8.1.3.140` 随依赖打包；达梦验证范围和完整 SQL 见 [达梦适配实测报告](docs/达梦适配实测报告.md)。

## 启动地址

- Windows：`start.bat 18088`；Linux：`./start.sh 18088`。端口参数省略时默认使用 `8088`。
- 启动脚本优先使用同目录 `runtime/`；目录缺失时仅为源码开发运行回退系统 Java，目录存在但不完整时直接报错，请重新解压完整交付包。
- 页面：`http://127.0.0.1:<启动端口>`
- 应用日志：`logs/light-db-migration.log`
- 加密配置：`data/last-database-config.dat`，密钥为同目录 `last-config.key`；`data/` 不进入 Git。

## 配置交付

开发人员在规则区配置完成后点击“导出配置”，将 JSON 文件交付现场。现场点击“导入配置”，选择不超过 5 MiB 的文件，即可回填任务类型、名称、批次和当前模式的迁移或归档规则。导入会替换页面当前规则；校验失败时保留原内容。

源库、目标库的全部连接字段均不导出，导入文件中的连接字段也会忽略，不覆盖页面现有连接或本机加密记忆配置。导入只回填表单，不创建或启动任务；归档删除确认需由现场完成备份核对后重新勾选。配置文件包含 SQL 和表名，交付前请按项目要求审阅其中的业务条件。

## 数据归档安全边界

- 归档只允许在一个数据库连接内完成，不支持跨库删除源数据。
- 多张主表按页面顺序依次归档，每个主表仍按批次独立提交；后续主表失败不会回滚此前已经提交的其他主表批次。
- 主表查询必须返回源表全部字段。主表和每张子表填写游标时按递增唯一字段执行固定上界 Keyset 分页；留空时不把主键视为递增游标，而是读取完整主键（支持任意列数的复合主键）作为稳定排序及精确删除键，每批删除后重新读取当前首批。无主键表必须手工填写递增唯一游标。
- 从表关系不允许上级节点不存在、自关联或循环；一个从表节点只允许选择一个直接上级节点，但一个节点可以关联多张下级从表。
- 归档表必须提前创建且与对应源表结构相同；归档使用严格插入，目标重复键会导致当前批次回滚，不会忽略重复后删除源数据。
- 正式执行前必须完成备份并安排停写或维护窗口；工具按批次提交，不提供已提交批次的自动恢复。

## 当前边界

- 工具不会自动执行建表或改表；结构校验失败时只生成需要人工审核的目标表结构同步建议脚本。
- 不支持存储过程、SQL 占位参数、任务断点持久化和执行后自动恢复。
- 暂停、终止按当前数据库操作或批次边界生效；已经提交的批次不会自动回滚。
